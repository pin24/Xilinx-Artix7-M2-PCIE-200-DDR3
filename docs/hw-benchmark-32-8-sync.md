# Тесты платы и сравнение FPGA vs CPU — конфиг 32/8 (синхронный data-путь)

Плата: NUM_MAC=32, ADDERS=8, DEVPROG_EN=1 (CORE_PARAMS=0x820), data-путь без async-конвертера.
Финальный коммит: `37e7fde`. Дата: 2026-10-26.

## 1. Функциональные тесты платы (все PASS)

| Тест | Ожидание | Результат |
|---|---|---|
| probe_core (MAGIC / CORE_PARAMS) | MAGIC OK, 0x820 | PASS |
| c2h (чтение DDR) | данные | OK |
| h2c (запись DDR) | успех | OK |
| **DDR-стресс 256КиБ round-trip** | bit-exact | **PASS** (бывший триггер deadlock) |
| device_prog single-dot | **3.5** | 3.5 EXACT |
| device_prog batch-GEMM | [[0,-2.25],[2,3.5]] | err **5.7e-10** PASS |
| Многоюнитная цепочка (src=prev) | H err 0; O err~6e-8 | PASS |
| Обучение 256с / 3эп | MSE падает | 0.95→0.78 |
| Обучение 1000с / 5эп | MSE падает | 0.85→0.31 (стабильно) |

## 2. Обучение MLP: FPGA vs CPU (end-to-end, ms/эпоху)

реальный датасет; F=2, O=1; batch=32; bs = батчей/эпоху.

| H | CPU ms/эп | FPGA ms/эп | ratio CPU/FPGA | Примечание |
|---|---|---|---|---|
| 16 | 0.14–0.39 | ~980 | **~0.0002x** | малая сетка, накладные FPGA |
| 64 | ~0.14 | ~485 | **~0.0003x** | |
| 512 | ~0.84 | ~503 | **~0.0017x** | |

Вывод: при host-ориентированном device_prog CPU быстрее на порядки для малых GEMM
из-за фиксированной накладной на запуск (DMA+GO+mailbox, ~0.3–1 с/эпоху) против
микросекундного numpy. Акселератор ценен как offload/детерминизм, не как ускорение малых батчей.

## 3. Широкий dot N_IN=1024 (throughput)

| | время | MFLOPs |
|---|---|---|
| CPU | 0.99 мкс | 2060 |
| FPGA (1 запуск device_prog) | ~15.4 мс | 0.13 |

Одиночный FPGA-dot несёт overhead запуска (~15 мс); выигрыш появляется только при
амортизации на сотнях/тысячах dot за один прогон (батч).
