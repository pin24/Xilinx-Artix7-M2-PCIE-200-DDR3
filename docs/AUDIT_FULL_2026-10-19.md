# ПОЛНЫЙ АУДИТ ПРОЕКТА A7_M2 — 2ch-pipeline (DDR3 + BRAM)

Дата: 2026-10-19. Сфера: RTL ядро, интеграция верхнего уровня, карта адресов, драйвер XDMA_DMA, тесты/нагру zones.
Ветка: 2ch-pipeline (clone 2chanle), HEAD bf1e18b. Read-only аудит; изменения спецификации — отдельный шаг по согласию.

---

## 0. Уточнение архитектуры «2 канала»

Аудит подтвердил: **«2 канала» = два набора DMA-каналов на хосте** с разной адресной трансляцией:
- `\h2c_0..3` / `\c2h_0..3` — **translateAxiBase = TRUE** (`file_io.c:56-63`): хост шлёт raw-offset от `0x80000000`, драйвер добавляет `XDMA_DDR3_AXI_BASE` (`dma_engine.c:880-881`). → DDR3.
- `\h2c_bram_0` / `\c2h_bram_0` — **translateAxiBase = FALSE** (`file_io.c:64-65`): хост шлёт полный картовый адрес (`0x10000000`=BRAM, `0x80000000+`=DDR3). База не добавляется.

Важно: BRAM-каналы — НЕ отдельные engine, а **тот же channel 0 с отключённой трансляцией**. Флаг живёт на общем движке → stateful (риск п.4.2).

Ядро tdot читает память через **один AXI4 master**; выбор DDR3 vs BRAM — декодом адресов в SMC (`0x80000000`→MIG, `0x10000000`→diag_bram_ctrl). Внутренних параллельных каналов data/weights нет — один общий FIFO, двухфазное последовательное чтение.

## 1. RTL ядро `tdot_axi4.sv` (1599 строк)

### 1.1 Регистровая карта (AXI-Lite, offset от REG_BASE=0x40023000)
Write: 0x00 CTRL.GO, 0x08 N_IN, 0x14/0x18/0x1C/0x20/0x24/0x28 адреса data/weights/result, 0x40 SCHED_CTRL, 0x44 SCHED_WPTR, 0x4C..0x58 DESC/COMP_BASE, 0x6C OBS_CTRL, 0xAC OBS_SNAP.
Read: 0x00 CTRL, 0x04 STATUS{DONE,BUSY}, 0x08 N_IN, 0x0C/0x10 RES0/RES1 (48 бит), 0x2C/0x30 CORE_RES0/1, 0x40..0x5C SCHED, 0x60 DONE_CNT, 0x64 CORE_PARAMS, 0x68 MAGIC('TDOT'), 0x6C OBS_CTRL-st, 0x70 BUILD_ID, 0x74 CAPS, 0x78..0xA8 OBS-счётчики, 0xB0..0xE0 SNAP.

### 1.2 AXI4 master
Read: INCR, ARSIZE=8Б, полный AXI-адрес из регистров, 4KB-кламп + кламп BURST_RD_LEN. Write: всегда 1 слово, WSTRB из зарегистрированного `wr_strb_q` (GAP-2-FIX).

### 1.3 Состояние
CS_IDLE/RD_DATA/RD_WEIGHTS/LOAD/RUN/WAIT/ACCUM_WAIT/WR/DONE/FETCH_DESC/SCHED_KICK/CMP1..3/T2F_WAIT + RST_{IDLE,ACT,DONE} для read.

### 1.4 Находки RTL
- **[СРЕДНИЙ] Тихий пропуск при невыровненном адресе**: `align_q`-фейл → задача тихо уходит в CS_DONE (строки 1270-1273/1207), без completion/статуса в планировщике и без записи результата. Индикация — только done=1 + RES=0.
- **[СРЕДНИЙ] fp32 пишет 8 байт при 4 полезных**: WSTRB=0xFF + `wr_data={32'h0,t2f}` (строки 1428-1430) — стирает старшие 4 байта слова при разделяемом буфере. FP32 на чипе не реализуем (998% LUT), актуально для мока.
- **[НИЗКИЙ] Хрупкая PACKED6-запись результата**: баррель зависит от фазы `(cstate==CS_ACCUM_WAIT)?add_res_w:core_result`; корректно только т.к. last-pass без аккумулятора всегда в CS_WAIT (строка 1076).
- **[НИЗКИЙ] Dead-параметры**: `RD_LEN_W` (166-168), `BURST_WR_LEN` (77) — не используются.
- **[НИЗКИЙ] Дублирование перехода** CS_WAIT и CS_ACCUM_WAIT non-last-pass — идентичный код дважды.
- **[НИЗКИЙ] BUILD_ID тип logic[31:0]** — параметр, а не generic-целое; не баг сам по себе (см. 2.1 о причине 0).

## 2. Интеграция `xdma_ddr3_core_top.sv` + BD + карта адресов

### 2.1 Причина BUILD_ID=0 (НАЙДЕНА — код build_flat.tcl)
- `build_flat.tcl:272` ставит `set_property generic BUILD_ID=32'h...` — корректно.
- `build_flat.tcl:322` затем ставит `set_property generic "NUM_MAC=.. ADDERS=.. ELEM_FMT=.."` — а `set_property generic` на fileset **заменяет всю строку**, не накапливает (документировано в самом скрипте 319-321).
- `BUILD_ID` НЕ включён в строку 322 → затирается. Синтез берёт дефолт `32'h0` топа. Audit-gate (339-348) BUILD_ID не проверяет → проходит молча.
- **Исправление:** добавить `BUILD_ID=32'h...` в единую строку 322 + доп. проверку в audit-gate.

### 2.2 Адресная карта FLAT (фактическая)
| Периферия | Адрес | Размер | В FLAT? |
|---|---|---|---|
| GPIO | 0x40020000 | 4K | ✅ |
| DataMover MM2S/S2MM ctrl | 0x40010000 / 0x40018000 | 4K | ✅ |
| TDOT regs | 0x40023000 | 4K | ✅ |
| XADC | 0x46000000 | 4K | ✅ |
| DFX Socket / ICAP / SPI | 0x40022000/0x40024000/0x40025000 | — | ❌ (только DFX, удалён) |
| **DDR3 (MIG)** | **0x80000000, 256MB (0x10000000)** | ✅ |
| **BRAM (diag_bram)** | **0x10000000, 8KB (0x2000)** | ✅ |

Маршрутизация M_AXI_TDOT: 0x80000000→MIG(M00), 0x10000000→diag_bram_ctrl(M01) (`xdma_ddr3_bd.tcl:727,731`).

### 2.3 Расхождения документации и кода
- ADDRESS_MAP.md описывает **DFX-сборку** (заголовок §1 `build_dfx.tcl`), фактическая активная — **FLAT**. §4/§9 (DFX Socket, RP-варианты) неактуальны.
- **BRAM 0x10000000 отсутствует в ADDRESS_MAP.md** вообще — реальный регион flat, используется ядром/хостом.
- ICAP/SPI/DFX Socket в ADDRESS_MAP перечислены как действующие — во FLAT не инстанцированы; SPI — STUB (non-blocking, 2026-10-11).
- Регистровые карты TDOT/XADC/GPIO RTL↔host — сходятся 100%.
- **[НИЗКИЙ] Двухдоменность BRAM-пути**: diag_bram_ctrl тактируется от PCIe-домена (axi_aclk), его мастера (tdot/DataMover) — от core-clk. Пересечение в SMC (CDC не проверен для burst).
- **[ОТКРЫТО] DIAG_EN=1 захардкожен** (top:278) и диагностический AXI-Lite порт сниффера не подключён (top:289-294) — в производственной прошивке.

## 3. Драйвер XDMA_DMA (dma_driver.c + libxdma + file_io.c)

### 3.1 Структура
Симлинк `\\.\XDMA0dma`, ноды control/user/bypass/h2c_0..3/c2h_0..3/h2c_bram_0/c2h_bram_0/event_0..15. GUID {74c7e4a9-...}. KMDF 1.15, SG64 duplex. Режим DMA по умолчанию INTERRUPT (poll #if 0).

### 3.2 Адресная математика
- `deviceOffset = DeviceOffset + bytesTransferred` (`dma_engine.c:870`).
- `if (translateAxiBase) deviceOffset += 0x80000000` (`dma_engine.c:880-882`).
- ROF-guard: reject если `endOff > 0x90000000` (корректно для 256MB DDR3). Только при translateAxiBase.

### 3.3 Находки драйвера (по приоритету)
- **[ВЫСОКИЙ] Race cancel↔IRQ**: `EvtCancelDma` (file_io.c:857-879) вызывает Release+Complete **без спинлока и без установки txnDone/isReqPending**. Гонка с DPC-путём → Release на уже освобождённой транзакции (UAF/0x10D). Guard `active!=request` отсекает только чужой запрос.
- **[ВЫСОКИЙ] Тихая обрезка DMA**: если `total > descBankLens`, код клампит `total=descBankLens` (dma_engine.c:929-934) и продолжает; оставшиеся SG-байты не переносятся, но запрос завершается «успешно» — потеря данных без кода ошибки.
- **[СРЕДНИЙ] translateAxiBase stateful на движке**: открытие `\h2c_bram_0` переопределяет трансляцию для всего channel 0 (file_io.c:189-196) — одновременный доступ двух клиентов ломает адресацию.
- **[СРЕДНИЙ] Лимит 8MB**: >XDMA_MAX_TRANSFER_SIZE не поддерживается; движок на этой плате 2..N пакеты не исполняет (dma_engine.c:722,1014-1021) → большие IRP — hang/неполные.
- **[СРЕДНИЙ] Head-of-line**: event-нода синхронно KeWaitForSingleObject(3s) в Sequential default-очереди (file_io.c:893-951) — блокирует остальные запросы до 3с.
- **[НИЗКИЙ] IOCTL GET_VERSION/PERF_STOP не реализованы** (декларированы в xdma_public.h, нет case → STATUS_NOT_SUPPORTED).
- **[НИЗКИЙ] Потенц. div-0** в `DescriptorIsAligned` (`% engine->alignAddr/alignLength`, dma_engine.c:573-575) — значения из регистра без проверки на 0.
- **[НИЗКИЙ] UB сдвига** `1<<(6+pcieWidth)` при pcieWidth≥26 (dma_engine.c:565).

## 4. Тесты, бенчмарки, верификация

### 4.1 bench_tdot_auto.py (531 стр.) — полный поток
Открытие (open_device: XdmaWinDma(\\.\XDMA0dma)→Upstream→Linux→Driver) → само-детект MAGIC/CORE_PARAMS/CAPS → генерация данных по ELEM_FMT (ones/fp32+host-conv) → write_input h2c → set_addrs/n/GO → wait_done → read_result c2h → сверка (порог 1e-3/rel 1e-3) → нагрузка n=8/16/32/64 ×iters + замер. Режимы --mock/--unit/--input{auto,ones,fp32}. Не гоняет планировщик hw.

### 4.2 ПРОБЛЕМА: stress_platform.py ПОВРЕЖДЁН
Файл `pytorch_layer/stress_platform.py` (10412 байт) — **все байты 0x00**. Параллельный нагрузочный тест (NDOT+MDMA+XADC, --sec/--dots/--dma/--n/--interval/--csv) недоступен. Восстановлен только из docs/STENDBENCH_2026-10-08.md.

### 4.3 Находки в тестах
- **[СРЕДНИЙ] div-by-zero в xdma_driver.py:1221-1222**: `h2c_mbs=args.size/(t1-t0)` не защищено (в отличие от obs_smi.py, где гарды стоят строки 99-100/131-132/118-119).
- **[СРЕДНИЙ] Дед-код эмуляторов**: edge_cases.py/emulate_test.py используют старую DFX-карту (TDOT=0x40003000, GPIO=0x40000000), не соответствуют flat (0x40023000/0x40020000). Эмулятор пишет RES0=0xDEAD — проверки на структуру, не арифметику.
- **[НИЗКИЙ] Устаревшие пути Vivado** в verify-скриптах: 2021.2 в rtl/verify_rtl_*, 2025.2 в интеграционных — непереносимо без правки.
- **[НИЗКИЙ] TB без сброса DONE** между кейсами; always #5 (100MHz) против 125MHz реальной сборки.
- README.md описывает DFX (`make build_dfx`) — устарел, актуален flat.

### 4.4 Пробелы покрытия
1. **Write-аудит DMA** — нет проверки полноразмерной записи ядром через пересечение с данными.
2. **Планировщик hw на плате** — только симуляции *x.sv; bench не гоняет SCHED.
3. **ELEM_FMT=1 на чипе** — нереализуемо (998% LUT); fp32→tf48 host-конверсия доверена скрипту, аппаратный F2T для fmt 0/2 не участвует.
4. **XADC/температура** — BUG-031 (XADC занят MIG), monitor почти всегда INVALID.
5. **`scripts/tests/` пуст** — нет ни одного unit-теста.
6. **BRAM-каналы (h2c_bram/c2h_bram) НЕ покрыты** ни тестами, ни бенчма; ядро ходит в DDR3, BRAM-путь в верификации не участвует.
7. Нет единого автом. раннера регрессий (нет Makefile-таргета; запуск вручную).
