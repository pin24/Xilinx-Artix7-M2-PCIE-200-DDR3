# 03. Как написать программу слоёв (device_prog)

`device_prog` — интерпретатор, который **сам** разворачивает «программу слоёв»
(описанную unit-таблицей в DDR) в последовательность dot-задач для ядра и пишет
mailbox-статус. Это снимает ~15 мс оверхеда на задачу (host вмешивается только
на границе батча).

## Формат unit-таблицы (в DDR, table_base, 32 байта/unit = 4×64-бит слова)
Адреса — полные AXI (в окне DDR `0x8000_0000..0x8FFF_FFFF`).

| Слово | Поле | Описание |
|---|---|---|
| W0 | `w_addr[63:0]` | базовый адрес весов слоя |
| W1 | `out_addr[63:0]` | базовый адрес результата слоя |
| W2 | `{ n_in[15:0], b_addr[47:0] }` | число входов, базовый адрес смещения |
| W3 | `n_out[15:0]`, `pass[31:16]`, `flags[39:32]`, `tag[55:40]`, `n_batch[63:56]` | см. ниже |

**<ВАЖНО>** RTL читает `n_in` из `uw[2][63:48]` (старшие 16 бит W2), НЕ `[15:0]`.
Host обязан паковать `W2 = (n_in << 48) | b_addr`. При n_in=0 движок запросит 0 слов
и повиснет в CS_RD_DATA. (В `test_dprog_single_dot.py` так и сделано.)

Поля W3:
- `n_out` [15:0] — число выходных нейронов слоя.
- `pass` [31:16] — число проходов (≥1). Проход 0 считает вход из `src`; проходы k>0
  гонят собственный выход обратно на вход (feed-forward повтор).
- `flags` [39:32]: bit0=relu, bit1=b_en(смещение), bit2=src(0=data, 1=prev).
- `tag` [55:40] — тег юнита (пробрасывается в mailbox).
- `n_batch` [63:56] — число строк данных (0 = 1). Batched GEMM.

## Интерпретация (вложенность циклов)
```
L1: for each unit u in [0, n_units):
L2:   for pass k in [0, pass):
L3:       for neuron j in [0, n_out):   # dot задача
L4:           (n_batch строк данных: task_a = data_base + batch*n_in*8)
```
- `src=data` → вход = `data_base` (буфер батча); `src=prev` → вход = `out_addr`
  предыдущего юнита.
- `w_col_j = w_addr + j*n_in*8`; `out[j] = out_addr + j*8`.

## Запуск программы (host)
1. Записать data/weights в DDR (h2c DMA) по известным адресам.
2. Записать unit-таблицу в `table_base` (DDR, h2c).
3. Через AXI-Lite задать регистры (в `rtl/integration/tdot_axi4.sv`):
   - `0xE8` DP_DATA_BASE, `0xEC` DP_TABLE_BASE, `0xF0` DP_MBOX_BASE (полные AXI адреса).
   - `0xE4` DP_CTRL = (n_units<<16) | GO(bit0).
4. Дождаться, пока `active` спадет (mailbox/задачи долетели), затем прочитать результат
   из out-адресов и статус из mailbox (c2h).

Mailbox (16 Б): W0={48'h0, tag}, W1={40'h0, units_done[15:0], status[7:0]}. status=0 = OK.

## Адреса и окно
- Все адреса задач обязаны попадать в окно `in_win`: DDR `0x8000_0000..0x8FFF_FFFF`
  или diag-BRAM `0x1000_0000..0x1000_1FFF`. Иначе задача ретирится (DP_STALL_BADADDR).
- Единицу data/вес результат считаем 8 байт (TFloat48 в 64-битном слове).

## Ограничения
- **n_in ≤ MAX_N_TOTAL = 32×NUM_MAC** (на 32/8 = 1024). Выше — sat (неверный результат).
- **n_in лежит в [63:48] W2** (не [15:0]).
- **Буфер скрытого слоя** (batch-результаты B×H×8) должен влезать в DDR-область,
  задаваемую скриптом (`--mem`, см. 06). Правило: `B×H×8 ≤ mem` (по умолч. mem=2М).
- `n_batch` — 8 бит (≤255).

## Рабочие примеры
- `scripts/test_dprog_single_dot.py` — один 4-dot: data[0.5,-0.25,1,0.5]·[1,2,-0.5,8]=3.5.
- `scripts/test_dprog_batch_board.py` — batched GEMM (n_batch).
- `scripts/debug_dprog_chain.py` — цепочка unit'ов со `src=prev` (feed-forward).
- `scripts/train_dprog_batch_mlp.py` — 2-unit программа (hidden+out) с n_batch (обучение).

## Как писать свою программу (шаги)
1. Определи слои (hidden/out), ширины (n_in, n_out), число строк батча (n_batch).
2. Выдели DDR-буферы (data, w[слой], out[слой]) — через `--mem`/layout в бенч-скрипте
   или вручную в пределах окна 0x8000_0000..0x8FFF_FFFF и mem (85% DDR).
3. Собери unit-таблицу (4 слова на unit) по формату выше, обязательно `n_in<<48`.
4. Запиши data/weights/таблицу в DDR, задай DP-регистры, GO.
5. Прочитай результаты + mailbox status (0=OK).
