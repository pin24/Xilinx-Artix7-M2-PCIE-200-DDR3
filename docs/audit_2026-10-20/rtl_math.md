## Находки

### P1-1. Конфликт раскладки поля E в 48-битном слове между RTL и программной моделью
- Файлы: `rtl/block/tfmul.sv:17` (`{E(8), M(40)}`, `a_e=a[47:40]`), `rtl/block/tfmac.sv:5` (`byte[5]=E, byte[4..0]=M`), `rtl/block/tfadd48.sv:35-41` (`unpack_e` читает `v[40+2*i+:2]`) против `ternary_sw/block/tfloat48.py:14-16` (`byte[0]=экспонента`, `_E_SHIFT=0` → E в битах `[0:8]`).
- Сценарий: программная модель кодирует/декодирует экспоненту в младшем байте `[0:8]`, RTL — в старшем `[47:40]`. Если 48-битное слово передаётся между ПО и RTL как сырое целое (мантисса в полях разной позиции), любое число будет прочитано с экспонентой в «чужом» месте → неверное значение/NaN. Прямая противоположность в документации формата обеих сторон.
- Рекомендация: зафиксировать единый номер байта поля E (например E=byte[0]=биты[0:8]) и привести все три модуля к соглашению; держать свидетельство эквивалентности `rtl_vs_arith48.py` как регрессионный тест. Вердикт: **PLAUSIBLE** (не доказано, что обвязка/детектор не разворачивают байты; сами спецификации прямо противоречат).

### P2-1. Неполная проверка ERR в dot-модулях: err_out смотрит только 2 трита экспоненты
- Файлы: `rtl/rtl/compute_core_dot.sv:186-187`, `rtl/rtl/compute_core_dot_pipe.sv:250-251`:
  `err_q <= (dot_res[0+:2]==TRIT_ERR) || (dot_res[2+:2]==TRIT_ERR);`
- Сценарий: проверяются только триты E0,E1 (биты [0:4]). ERR-код (2'b11) в трите E2..E4 или в любом из 15 тритов мантиссы (биты [10:40]) остаётся незамеченным → результат-«мусор» помечается как валидный, NaN просачивается как нормальное число.
- Рекомендация: сканировать все триты 40-битного слова (сумма/OR по `is_err` для каждого трита), например циклом, как `_has_err` в Python. Вердикт: **CONFIRMED**.

### P2-2. CDC без синхронизатора в xadc_temp: raw_valid из clk50 в axi-домен
- Файлы: `rtl/integration/xadc_prim.sv:109-128` (raw_valid — импульс в домене clk50) → `rtl/integration/xadc_temp.sv:134` (`if (raw_valid) temp_val<=raw_temp;` тактируется S_AXI_ACLK=125 МГц).
- Сценарий: single-cycle pulse `raw_valid` из 50 МГц в 125 МГц без 2FF. Данные стабильны и пульс шире периода axi (20 нс vs ~8 нс) — двойной защелок вреда не даёт, но это формальное нарушение CDC (метастабильность флага, возможный пропуск или сдвоенный латч).
- Рекомендация: добавить 2FF-синхронизаторы на `raw_valid`/флаг новизны (или продублировать импульс на несколько тактов axi). Вердикт: **PLAUSIBLE** (риск низкий при current_clock ratio, но нарушение корректно зафиксировано).

### P2-3. diag_axi_sniffer: счётчик read-timeout — no-op заглушка, но отдаётся в регистре
- Файл: `rtl/diag/diag_axi_sniffer.sv:189` (`cnt_r_timedout <= cnt_r_timedout; // no-op placeholder`), регистр открыт на offset `6'd16` (строки 157).
- Сценарий: диагностический «read timeout» никогда не инкрементируется, хотя хост при чтении `0x10` видит ноль и может принять его за «нет таймаутов». Мислидинг при отладке DDR3/DMA.
- Рекомендация: либо реализовать реальный таймер AR→R, либо убрать регистр/документировать как нереализованный. Вердикт: **CONFIRMED** (аппаратура/логика соответствуют описанию «placeholder»).

### P3-1. spi_over_pcie (заглушка): write-канал требует AW и W в одном такте
- Файл: `rtl/integration/spi_over_pcie.sv:89` (`if (S_AXI_AWVALID && S_AXI_WVALID)`), `awready=SR(S_AXI_AWVALID)`, `wready=...`.
- Сценарий: при декуплд-мастере, подающем AW и W в РАЗНЫЕ такты, транзакция никогда не коммитится (bvalid не выставляется, awready/wready сняты) → write «вечно busy»/зависание — ровно сценарий, который большие защёлки в tdot_axi4/xadc_temp уже лечат. Для заглушки, чьё назначение — «не вешать шину», это расхождение с образцом.
- Рекомендация: если модуль сохраняется как stub, привести write-канал к независимым защёлкам AW/W (как в xadc_temp/icap_ctrl). Вердикт: **PLAUSIBLE**.

### P3-2. diag_axi_sniffer включён в по умолчанию (DIAG_EN=1) и затягивает мёртвую AXI-Lite логику
- Файлы: `rtl/integration/xdma_ddr3_core_top.sv:277` (`localparam int DIAG_EN = 1;`), инстанс `u_diag` (строки 280-307) с s_axi входами, прибитыми к 0.
- Сценарий: в штатную (не-тестовую) сборку по умолчанию попадают счётчики/защёлки AXI-Lite slave, что считывалось только watch-only. Читательская часть dead (s_axi tied 0) — трата флопов, плюс `.mig_init_calib_complete(1'b0)` и `.mig_mmcm_locked(1'b0)` дают заведомо ложный статус по регистру 0x0B.
- Рекомендация: `DIAG_EN` по умолчанию = 0 для продакшена, включать вручную/ifdef при диагностике. Вердикт: **CONFIRMED** (по коду).

### P3-3. icap_ctrl: нет таймаута ack mailbox
- Файл: `rtl/integration/icap_ctrl.sv:171-193` (mailbox) — `in_flight` сбрасывается только по `ack_edge`; таймаута на зависший slow-домен нет.
- Сценарий: если FSM окна выборки slow-домена заклинивает (или слово не доставлено), mailbox остаётся busy вечно → ядро write в DATA получает бессрочный backpressure. Фактический риск низкий: slow-FSM имеет default→IDLE и уничтожается STOP.
- Рекомендация: добавить watchdog на `in_flight` (сброс по N тактов axi). Вердикт: **PLAUSIBLE**.

### P3-4. tbyte_mul: `default: return 5'h00` в asm_tab маскирует возможный пропуск ключа
- Файлы: `rtl/block/tbyte_mul.sv:55-104` (`asm_tab`), `default: return 5'h00` (строка 102).
- Сценарий: если легальный ключ {coeff∈[-6,6], carry∈[-1,1]} отсутствует в таблице, он молча даёт 0 (трит 0, перенос 0) вместо корректной balanced-сборки — тихая неверная цифра результата. Комментарий (строка 54) утверждает «45/45 валидных ключей», что по тестам подтверждается, но default-0 защищает от ошибки, а не сигнализирует.
- Рекомендация: для строгости добавить синтез-ассерт/полный перебор всех 45 ключей как регрессию. Вердикт: **PLAUSIBLE** (защита от пропуска не подтверждена автотестом в репо).

2. **tbyte_mul.sv — asm_tab:** balanced-сборка coeff+carry∈[-6,6]; заявлено 45/45 ключей, default→0 (см. P3-4). ✅
3. **compute_core_dot.sv:** полный сброс всех регистров (phase, ci, p_idx, prod_cnt, t_lvl/t_idx/t_cnt/t_dst, m_*, буферы a_tf/b_tf/prod/pbuf). Сброс в середине вычисления корректно возвращает в PH_IDLE. ✅
4. **compute_core_dot.sv:** порядок подачи/защёлки пар mul (prod[p_idx-1] = результат пары p_idx-1) не смещён; последняя пара через доп. такт PH_MUL_LAST. ✅
5. **compute_core_dot_pipe.sv:** полный сброс всех регистров и буферов; паузы конвейеров (1 valid на 2 такта) изолируют пакеты — известная проблема дубликата последнего пакета исключена. ✅
6. **compute_core_dot_pipe.sv:** комбинационные mux защищены от X при выходе за границы (f2t_sel/mul_a_sel/add_a_sel с guard `cv_i<N` / `cm_i<N` / `ca_i<t_cnt`). ✅
7. **tfadd48.sv:** распаковка (произведение 40 тритов, экспонента, знак старшего ненулевого трита) согласована с конвенцией compute_dot_par_raw/tfadd_raw; ноль корректно определяется. ✅
8. **tfmul.sv / tfmac.sv:** нормализация (`val_ge_p19`→/3, `val_lt_p18`→×3, `e>40`→ERR, `e<-40`→0) корректна; насыщение ERRR через `{TOTAL_ERR8,TOTAL_ERR40}`; underflow→0. Денормальные значения обрабатываются. ✅
9. **xadc_prim.sv:** DRP-FSM (DADDR 0x00→0x06→idle) с ожиданием DRDY — без зависаний; таймер 1с не переполняет 26-бит (50e6<2^26). Не заглушка — реальный примитив XADC. ✅
10. **xadc_temp.sv:** независимые защёлки AW/W и защита AR от перезаписи при висящем rvalid (паттерн из tdot_axi4); read-only запись не меняет регистры. ✅ (единственный дефект — CDC, P2-2).
11. **spi_over_pcie.sv:** это документированная НЕ-заглушка, а совместимый stub — НЕ инстанцируется в активных битстримах (порт S_AXI_SPI_REGS из BD убран); STARTUPE2/QSPI-пины не дублируются, JTAG-flash свободен от 27-3347. Ответ по read (STATUS DONE=1, BUSY=0) корректный, зависание read нет (см. P3-1 по write). ✅
12. **icap_ctrl.sv:** полный синхронный сброс slow-домена (icap_rst_n async assert / sync deassert); CDC через toggle-handshake с 2FF ASYNC_REG на всех путях (req/go/stop fast→slow, ack/busy slow→fast). 2-тактовое окно CSIB, предустановка данных и ack ПОСЛЕ подъёма CSIB — соответствует UG470. STOP аварийно закрывает окно и возвращает ack (mailbox не зависнет). ✅
13. **diag_axi_sniffer.sv:** чисто наблюдатель — m_axi* только входы, выходов в шину нет, комбинационного пути «через него» не создаёт; подсчёт AW/W/B/AR/R/RRESP/BRESP корректен (за исключением no-op таймаута, P2-3). ✅
14. **Синтезируемость:** `initial`/`$display`/`$readmemh` в синтезируемых модулях скоупа отсутствуют; больших case (значительно > декод таблиц) нет; комбинационные mux/циклы тритов — константные распараллеливаемые сетки, не асинхронные пути.
