# Проблема и план исправления h2c-wedge (2026-10-22)

## 1. Проблема (подтверждена на железе, 2/2 power-cycle)

Одиночная **4 КиБ** h2c-запись (1 дескриптор) случайно вешает движок XDMA.
Воспроизводимость и замер (узел `\\.\XDMA0dma`, `perf_start`/`perf_get` IOCTL 0x1/0x3):

| Атрибут | Значение |
|---|---|
| Сценарий | 64 Б round-trip OK → одиночная write_dma 4 КиБ @0x200000 |
| Результат | `timeout at 0x200000` (164.7 с) на **1-й** попытке (2/2 power-cycle) |
| `perf_get` на клине | `dataCycleCount=256`, `pendingCount=0` |
| h2c регистры | `status=0` (снят драйвером после таймаута), `completed=1` |
| c2h регистры | `status=BUSY`, `completed=0` |
| IRQ | `channelIntPending=0` |
| DIAG | `bytesTransferred=0` (host-IRP не завершён) |

### Интерпретация
4 КиБ = 256 бит × 16 байт (128-бит AXI). `dataCycleCount=256` при старте 0 → **движок выдал на AXI ровно все данные записи**, но передача не завершилась:
- `B`-ответ (или счётчик завершённых дескрипторов) так и не вернулся;
- вслед за h2c виснет c2h (`BUSY`, `completed=0`) — поражён **общий downstream-путь**;
- IRQ не взведён, host-IRP не завершается.

То есть клин **не** в движке, **не** в фетче дескриптора, **не** в размере/длине цепочки (1 дескриптор!), а в **пути write-response/completion**:
`xdma_axi_smc (S00=XDMA M_AXI) → async CDC 125→100 МГц → MIG (DDR3)`.

### Исключено
- **H10** (структурный бюджет длины цепочки) — длина 1 дескриптора, клайн есть.
- **Митигация A** («ограничить размер/длину») — одиночная 4 КиБ уже вешает.
- **Движок/фетч/IRQ** — данные выданы, pending=0.

## 2. План исправления

**Выбран вариант 2: отдельный SmartConnect-путь для XDMA к MIG** (снижает head-of-line/арбитраж с tdot + 2× DataMover на общем SI->MI00). CDC 125→100 остаётся (см. Резерв).

При повторении клина на варианте 2 — **вариант 1: единый клок** (`axi_aclk` = `MIG ui_clk` = 100 МГц): убирает async-CDC в SMC write-пути, главный подозреваемый. Цена −20% полосы PCIe.

Шаги:
1. [DONE] Диагностика: лестница + `perf_get` → локализация «write-response/completion».
2. [DONE] Коммит/пуш описания проблемы и плана (этот документ).
3. Внести исправление в BD: отдельный SI для XDMA (или в temp-копии flow, затем перенос).
4. Эмуляция и аудиты всеми доступными агентами (RTL/BD, драйвер, регистры/протокол, постмортем).
5. Готовность к сборке прошивки (NUM_MAC=32 ADDERS=16 DEVPROG_EN=1, RING-1024, RING_DEPTH, BUG-083/084/085).
6. Прошивка, репро 512/4 КиБ, подтверждение устранения.

Резервные кандидаты (если вариант 2 не снимет): единый клок (вар. 1), write-приоритет MIG, выделенный порт MIG.

## 3. Репозиторий/сборка
- Прошивка на плате: 32/16, DEVPROG_EN=1, flat, кольцо 1024 (в исходниках), до GLOBAL_RETIMING.
- Сборка: `vivado -mode batch -source scripts\build_flat.tcl -tclargs NUM_MAC=32 ADDERS=16 DEVPROG_EN=1 JOBS=4`.
- Эмуляция: `verify_tdot_axi4.py`, `tb_timeout_abort`, `xvlog/xelab/xsim`.
