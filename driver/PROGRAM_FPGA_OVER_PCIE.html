По PCIe нельзя прошить «пустую» FPGA — без работающего PCIe-эндпойнта нет канала. Для этого только JTAG/флеш (см. driver/R-01_BUILD_AND_FLASH.md).

Как запускать

cd C:\A7_M2\Xilinx-Artix7-M2-PCIE-200-DDR3\pytorch_layer

:: разбор файла без обращения к железу
C:\Python39\python.exe program_fpga_icap.py ..\build\artifacts_dfx\xdma_ddr3_core_top.bin --dry-run

:: прогон без железа (in-memory ICAP) — smoke-тест скрипта
C:\Python39\python.exe program_fpga_icap.py ..\build\artifacts_dfx\xdma_ddr3_core_top.bin --mock

:: ПОЛНЫЙ образ по PCIe (линк просядет на ~5–10 c)
C:\Python39\python.exe program_fpga_icap.py ..\build\artifacts_dfx\xdma_ddr3_core_top.bin --full --yes

:: частичный (RP) — линк не рвётся
C:\Python39\python.exe program_fpga_icap.py ..\build\artifacts_dfx\partial_rp.bin --partial

Скрипт: разбор (sync 0xAA995566, LE-слова) → precheck STATUS (BUSY/READY) → GO → поток слов с ожиданием READY → STOP → отчёт. Коды возврата: 0 ok · 2 нужно --yes · 3 файл/формат · 4 precheck · 5 загрузка.

Регистры ICAP

Адрес (BAR0-rel)ИмяСмысл
0x40004000 +0x00CTRLbit0 GO (самосброс), bit1 STOP
+0x04STATUSbit0 READY (mailbox свободен), bit1 BUSY
+0x08DATAwrite-only, 32-бит слово (LE)

RTL: icap_ctrl.sv (ICAPE2 X32 @62.5 МГц). Альтернатива — Xilinx axi_hwicap на 0x40001000.

Ожидания и восстановление

  • Полный образ: PCIe отвалится на ~5–10 с; устройство вернётся. Если нет — power-cycle: FPGA поднимется из SPI-флеша (флеш не тронут) → безопасно.
  • Частичный: PCIe остаётся активным.
Проверка после прошивки: driver\build\test_xdma.exe gpio (строка BAR map), python pytorch_layer\xdma_driver.py --selftest, python pytorch_layer\dfx_swap.py --status.

Ошибка «неверный sync word 0xFFFFFFFF» (E-13)

Vivado-овские .bin/.bit для 7-серии начинаются с 48-байтовой преамбулы:

FF x32 | 00 00 00 BB 11 22 00 44 | FF x8 | AA 99 55 66 (sync) | ...

Первое LE-слово = 0xFFFFFFFF, а не sync → старый загрузчик падал. Исправлено: find_sync_offset() ищет sync в первых 1024 байтах и пропускает преамбулу (работает для полного и частичного образов). Ваши файлы: полный = 1 349 799 слов, частичный = 505 901 слово.

Результат проверки на железе (2026-09-12)

Полный образ передан по ICAP успешно (1 349 799 слов за 19 с, exit 0), ICAP STATUS до/после = 0x1, плата не пострадала. Но образ не применился: BAR0 после remove+rescan = 1024 КБ, GPIO_TRI без изменений, PnP-событий нет. При этом битстрим корректен (pf0_bar0_size=128 в собранном .xci).

Вывод: полная реконфигурация кристалла через ICAP не срабатывает. Штатные пути: полный образ -> JTAG/флеш (scripts/flash_program.tcl, R-01); частичный (RP) -> ICAP/DFX; постоянное обновление без JTAG -> SPI-over-PCIe + IPROG (нет в проекте, R-14).

Windows: штатный драйвер вместо xdma_rw.exe

На Windows Python-слой работает с вашим драйвером напрямую (\\.\XDMA0 через XdmaWinDriver) — xdma_rw.exe для регистров/ICAP не нужен (проверено: ICAP STATUS=0x1). xdma_rw остаётся только для DMA.

Ограничения

  • ICAP-прошивка временная (сбрасывается питанием); постоянно — только JTAG/флеш.
  • Полный образ должен быть совместим по PCIe/ICAP-инфраструктуре; иначе — power-cycle + JTAG.
  • Скорость mailbox-прошивки ~10–30 тыс. слов/с → полный образ ~40–100 с. Для скорости — JTAG/флеш.
  • Windows-путь требует xdma_rw.exe (риск R-05); Linux — /dev/xdma0_user.
