R-01 — Пересборка битстрима и прошивка платы (BAR0 = 128 МБ)

Проект: C:\A7_M2\Xilinx-Artix7-M2-PCIE-200-DDR3 · Vivado 2025.2 · 2026-09-11

Зачем

На плате обнаружен устаревший битстрим: измеренный BAR0 = 1 МБ против pf0_bar0_size=128 (128 МБ) в scripts/build_dfx.tcl. Следствия — недоступны регистры периферии (GPIO/TDOT/XADC не отвечают корректно). Нужно пересобрать и перепрошить флеш актуальным образом.

Шаг 1 — пересборка

cd /d C:\A7_M2\Xilinx-Artix7-M2-PCIE-200-DDR3
make build NUM_MAC=32 JOBS=8
:: либо напрямую:
"C:\AMDDesignTools\2025.2\Vivado\bin\vivado.bat" -mode batch -source scripts\build_dfx.tcl -tclargs NUM_MAC=32 JOBS=8

NUM_MAC=32 согласован с хост-софтом (TdotCore(num_mac=32), FpgaBackend(num_mac=32)). Дефолт Makefile — 8.

Проверьте в логе: === PCIe BAR REPORT === → BAR0: size=128; тайминг WNS/WHS/WPWS ≥ 0 (иначе артефакты не экспортируются).

Результат:

build\artifacts_dfx\
  xdma_ddr3_core_top.bit   - JTAG-загрузка в FPGA (volatile)
  xdma_ddr3_core_top.bin   - тело битстрима (ICAP/флеш)
  xdma_ddr3_core_top.mcs   - образ для SPI-флеша
  *partial*.bit / *.bin    - частичные битстримы RP (dfx_swap.py)

Шаг 2 — прошивка флеша (плата грузится сама)

Вариант A — скрипт (рекомендуется):

"C:\AMDDesignTools\2025.2\Vivado\bin\vivado.bat" -mode batch ^
  -source scripts\flash_program.tcl -tclargs build\artifacts_dfx\xdma_ddr3_core_top.bin

Скрипт повторяет проверенную последовательность (open_hw_manager → connect_hw_server → open_hw_target → xc7a200t_0 → create_hw_cfgmem w25q128jvq-spi-x1_x2_x4 → Erase/Program/Verify, ≈2 мин).

Вариант B — GUI: Open Hardware Manager → Open Target → Auto Connect → п.к.м. на xc7a200t_0 → Add Configuration Memory Device… → w25q128jvq-spi-x1_x2_x4 → Program (.mcs или .bin, галочки Erase/Program/Verify).

Вариант C — быстрая volatile-проверка: Program Device… → xdma_ddr3_core_top.bit (живёт до выключения питания).

Не отключайте питание/кабель до сообщения Program/Verify Operation successful.

Шаг 3 — проверка

  1. Полный power-cycle платы (загрузка образа из флеша).
  2. Диспетчер устройств → «Системные устройства» → «XDMA DDR3 Ternary Accelerator v1.1».
  3. driver\build\test_xdma.exe gpio
:: ожидается: BAR map: BAR0=131072 KB, BAR2=64 KB
  4. Тесты по одному: gpio · tdot · xadc · proto · icap · ddr3 (на актуальном образе: PASS; ddr3 → SKIP — в DFX DDR3 только через DMA).
  5. DMA-проверка: python pytorch_layer/xdma_driver.py --selftest --dot (Linux) / xdma_rw.exe (Windows, см. R-05).
Критерий закрытия R-01: BAR0 = 131072 КБ (128 МБ) после power-cycle + GPIO/TDOT/XADC/PROTO/ICAP проходят, ddr3 → SKIP.

Откат

  • JTAG-программа (вариант C) — volatile: power-cycle возвращает образ из флеша.
  • Нерабочий образ — перепрошить предыдущий .mcs/.bin или повторить шаг 1 на предыдущем коммите (git checkout <commit> -- rtl scripts constraints → make build).
  • Проблемы драйвера — driver/ROLLBACK.md, driver/HANDOFF.md.

Известные помехи: антивирус и проверка подписи

Vivado при старте проверяет подписи загружаемых библиотек. При агрессивном антивирусе (наблюдалось: 360 Total Security, служба QHActiveDefense) проверка может плавающе падать:

Unknown error occured while verifying the digital signature. Error Code: -2146869232
(0x80096010 = TRUST_E_BAD_DIGEST)
Подпись самого файла при этом валидна (проверено Get-AuthenticodeSignature), HashMismatch по lib\win64.o — 0 из 187; повторные запуски проходили успешно. Разбор — driver/ERROR-FIX-LOG.md (E-11), риск R-13.
Что делать: 1) исключения в 360 для C:\AMDDesignTools и каталога проекта; 2) просто повторить make build; 3) диагностика: scripts\check_vivado_signatures.ps1.
